# Чтение данных файловой базы 7.7

Данные читает установленная 1С 7.7 через OLE Automation (`V77.Application`).
MCP предоставляет только фиксированные операции чтения: произвольного BSL, SQL,
`ExecuteBatch`, записи объектов или проведения документов в интерфейсе нет.
Права пользователя базы продолжают действовать. Вход через OLE может выполнять
штатную инициализацию конфигурации и служебные действия платформы; это ограничение
интерфейса MCP, а не открытие файлов DBF с системным атрибутом read-only.

## Почему OLE

1sqlite — внешняя компонента для работающей 1С 7.7, зависящая от 1C++ и её доступа
к данным. Наличие DLL рядом с базой не делает её автономным драйвером DBF для Python.
OLE использует штатные ссылки, периодические реквизиты и бухгалтерские итоги.
Собственный разбор DBF потребовал бы повторить семантику документов и бухгалтерии.

Источники: [1sqlite](https://github.com/alyuev/1sqlite),
[1c-mcp-toolkit](https://github.com/ROCTUP/1c-mcp-toolkit).
Синтаксис 7.7 сверяется с `1cv7Lang.als` из установленной платформы.

## Запуск на Windows

Нужны Python 3.11+, зарегистрированный OLE-сервер 1С 7.7 и доступ к файловой базе.
`pywin32` устанавливается автоматически на Windows. Linux/Docker поддерживает
метаданные; чтение OLE требует запуска Python на Windows с установленной 1С.

```powershell
cd D:\pj77\77MCP
.\.venv\Scripts\python.exe -m pip install -e '.[dev]'
$env:MCP_DATA_DIR = 'D:\pj77\77MCP\data'
$env:MCP_MD_PATH = 'D:\pj77\db77\1Cv7.MD'
.\.venv\Scripts\python.exe -m mcp_1c77
```

Если окружение создано через `uv`, зависимости можно установить командой
`uv pip install --python .venv\Scripts\python.exe -e '.[dev]'`.

Откройте `http://localhost:8099/`. В разделе подключения укажите абсолютный путь
`D:\pj77\db77\1Cv7.MD`, пользователя и пароль. База — каталог выбранного MD;
отдельного независимого пути к данным нет. Пароль не сохраняется в настройках
и не передаётся агенту через MCP. Для новой сессии после перезапуска введите его снова.
`MCP_MD_PATH` только загружает метаданные; автоматического входа с паролем нет.

Загрузка MD через браузер даёт только метаданные: браузер не передаёт его исходный
каталог. Загрузка/перезагрузка метаданных отключает предыдущее соединение с данными.
Неудачное подключение к другой базе сохраняет прежнюю выбранную базу.

По умолчанию сервер слушает `127.0.0.1:8099`. Переменные `MCP_HOST` и `MCP_PORT`
меняют адрес и порт. Подключение базы разрешено только с этого компьютера.
Не публикуйте MCP в недоверенную сеть: отдельной аутентификации на чтение нет.

## Инструменты

| Инструмент | Назначение |
| --- | --- |
| `get_database_info` | Проверка соединения, источника и режима чтения |
| `read_catalog` | Элементы, реквизиты и ссылки справочника |
| `read_documents` | Шапки документов за период |
| `read_document_lines` | Табличная часть по ссылке из шапки |
| `read_accounts` | Счета бухгалтерского учёта |
| `read_accounting_postings` | Бухгалтерские проводки за период |
| `read_accounting_totals` | Начальные/конечные остатки и обороты по счетам |

Имя вида и пользовательские реквизиты берите из `list_objects` и `get_object`.
Имена системных полей справочника: `code`, `name`, `is_group`, `deleted`, `parent`,
`owner`; документа: `reference`, `number`, `date`, `posted`, `deleted`.
`fields` ограничивает возвращаемые поля, `filters` задаёт точное равенство
скалярным значениям. Не используйте выражения BSL в именах и фильтрах.
Период задаётся датами `YYYY-MM-DD`, обе границы включены.

Списки ограничены `limit` от 1 до 500 и `offset` от 0 до 100000. Следующую страницу
запрашивайте по `next_offset`, пока `has_more` истинно. `offset` относится к
отфильтрованным строкам. Общий размер выборки заранее не рассчитывается.
Один запрос ограничен 60 секундами; после тайм-аута нужно подключиться заново.

Результаты чтения имеют `success`, `data` и `source` с каталогом базы.
Ошибки имеют `success: false`, `code` и `error`; ошибка не выдаётся за пустую выборку.
Числа для сверки не следует преобразовывать в двоичный float: используйте Decimal.
Ссылки базы 7.7 нельзя сравнивать напрямую со ссылками 8.3.

## Сверка с 8.3

1. Проверьте `get_database_info` и одинаковый период в обеих базах.
2. Сопоставьте справочники по согласованному бизнес-ключу: коду, ИНН или артикулу.
3. Сопоставьте документы по виду, номеру, дате и организации; затем строки по номенклатуре.
4. Сверьте СНД/СНК, ДО/КО, СКД/СКК одинаковых счетов через `read_accounting_totals`.
5. Для расхождений прочитайте проводки через `read_accounting_postings`.

Отдельные вызовы не образуют общий транзакционный снимок. Для воспроизводимой
сверки используйте согласованную копию базы или интервал без изменений данных.
Учтите различия плана счетов, аналитик, валют и правил проведения между 7.7 и 8.3.

## Обслуживание и откат

Изменять конфигурацию 7.7 и загружать обработки не требуется. Сначала отключите
базу кнопкой в интерфейсе, затем остановите сервер. Для отката верните версию
77MCP до добавления чтения данных. Приложение не регистрирует COM автоматически.
При `ole_unavailable` проверьте установку/COM-регистрацию поставки 1С и создание
`V77.Application`; копирования одного exe может быть недостаточно.
